You are building my personal portfolio website.

This is not a conventional portfolio site with a hero section, navbar, cards, and sections stacked vertically.

The website itself is an interactive room.

I have provided two visual references:

1. `docs/mockup.png`
   - This is the UX/art-direction reference.
   - It shows roughly how interactive objects in the room map to areas of the site.
   - Do NOT blindly reproduce every floating label/card from this mockup.
   - Treat it as a concept diagram for the experience.

2. `docs/room-background.png`
   - This is the clean visual reference for the room itself.
   - The final landing scene should stay extremely faithful to this image in composition, atmosphere, proportions, lighting, color palette, clutter, and mood.
   - This image defines the visual identity of the site.

Before writing code:
- inspect both images carefully
- inspect the existing repository

==================================================
CORE CONCEPT
==================================================

The landing page opens directly into this room.

The room is the navigation system.

There should NOT be a traditional visible navigation bar containing:

About
Projects
Skills
Hobbies
Contact
etc.

Instead, major physical objects are interactive.

The initial object mapping is:

- LEFT COMPUTER / CRT / WORKSTATION
  -> Portfolio / Projects

- BED
  -> Spare Time / Hobbies / Music / Gaming / personal interests

- ARMCHAIR
  -> About Me

- RIGHT-SIDE SHELVES / TECH / EQUIPMENT
  -> Skills / Tooling / Technologies

- CITY / WINDOW
  -> Contact / Vision / links

- SMALL OBJECTS / DEVICES ON FLOOR
  -> Experiments / Playground / side projects

This mapping should be implemented as data/configuration rather than hard-coded separately throughout the application.

For example, conceptually:

const sceneAreas = [
  {

    label: "Portfolio / Projects",
    target: ...,
    camera: ...,
    content: ...
  },
  ...
]

Do not turn this into:

- a generic portfolio with cyberpunk styling

"interactive cinematic space"

rather than:

"website placed on top of an illustration"

==================================================
2.5D / 3D STRATEGY
==================================================

We only have reference images, not actual 3D models of the room.

Do NOT invent a completely different generic 3D bedroom.

The visual match with the reference is more important than technically having every object represented by geometry.

Use a hybrid / 2.5D approach initially.

A good implementation would be:

- place the reference environment inside a Three.js scene
- use the clean background image as the primary visual plate
- create invisible interaction geometry over the important objects
- optionally separate certain foreground objects into layers if doing so materially improves parallax
- add very subtle camera parallax from cursor/device movement
- use an actual Three.js camera for navigation transitions
- maintain perspective and depth illusion
- allow later replacement of visual layers with proper GLTF geometry

The architecture should NOT prevent us from eventually replacing parts with real 3D assets.

Create scene-specific code separately from content/UI code.

For example:

src/
  app/
  scene/
    RoomScene.tsx
    CameraController.tsx
    InteractionManager.tsx
    SceneHotspot.tsx
    sceneAreas.ts
  sections/
    Projects/
    About/
    Hobbies/
    Skills/
    Experiments/
    Contact/
  components/
  styles/

Exact structure can differ if the repository already has conventions.

DISCOVERABILITY
==================================================

Interactive objects need to be discoverable without destroying immersion.

Use subtle techniques such as:

- slight highlight on hover
- cursor change
- tiny ambient outline
- localized light/glow
- small contextual label appearing near the object
- very subtle hotspot
- slight object-scale or lighting response

Example:

  monitor subtly brightens
  small text appears:
  "Portfolio / Projects"

Hover the bed:
  subtle warm highlight
  "Spare Time / Hobbies"

The effect should be restrained.

Do not put six permanent giant floating cards across the screen.

==================================================
OBJECT INTERACTION
==================================================

When an object is activated:

1. lock competing interactions
2. smoothly move the camera toward the selected area
3. subtly alter depth/parallax
4. transition into the selected section
5. reveal its content as something physically connected to the room

The animation should feel deliberate and cinematic.

Approximate transition duration:
600–1000ms

Use smooth easing, not linear movement.

Avoid motion that causes nausea.

==================================================

- precise object interaction

Tablet:
- same concept
- larger hitboxes
- less aggressive camera movement

Mobile:
- preserve visual identity
- disable expensive or awkward effects if necessary
- tap targets must be large enough
- hotspot labels can be more explicit
- interaction cannot depend on hover
- use dvh correctly
- safe area insets
- no accidental page scrolling during room interaction

==================================================
PERFORMANCE
==================================================

Performance is important.

Targets:

- good experience on modern laptops
- acceptable integrated GPU performance
- avoid needless permanent render loops
- preload important assets
- defer secondary content
- optimize textures
- use correct DPR limits
- avoid enormous uncompressed textures
- avoid excessive post-processing
- avoid particles just because this is "cyberpunk"

Use adaptive DPR where appropriate.

Do not render at devicePixelRatio 3 or 4 unnecessarily.

Cap something like:

Math.min(window.devicePixelRatio, 2)

or lower if testing shows that is preferable.

Respect mobile devices.
